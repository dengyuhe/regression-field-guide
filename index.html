00Setup & imports

One import cell at the top keeps the rest of the notebook short. Load train and test together so you can compare them early.

import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
import seaborn as sns
import statsmodels.api as sm
from itertools import combinations
from sklearn.model_selection import KFold, cross_val_score
from sklearn.linear_model import LinearRegression, Ridge, RidgeCV, Lasso, LassoCV, HuberRegressor
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline
from sklearn.ensemble import HistGradientBoostingRegressor, RandomForestRegressor

df   = pd.read_csv('train.csv')
test = pd.read_csv('test.csv')
X, y = df.drop(columns='Y'), df['Y']

01Data inspection

Check data quality, look at every relationship with Y, and spot structure that a linear model will miss.

Shape, types, missing values, duplicates

library: pandas

print(df.shape)
print(df.dtypes)
print(df.isna().sum())
print(df.duplicated().sum())                 # same X and same Y
print(df.duplicated(subset=X.columns).sum()) # same X, Y may differ
df.describe()
  • Exact duplicate rows with continuous features are almost always a logging error: drop them with df = df.drop_duplicates(). Left in, they leak between CV folds.
  • Missing values: df.dropna() if few, otherwise df.fillna(df.median()), and say which you chose.
  • Outliers: compare min and max with the quartiles in describe().

Correlation matrix

library: seaborn

sns.heatmap(df.corr(), annot=True)   # df, not X, so Y is included

A correlation near zero only rules out a linear relationship. Always check the scatter plots before discarding a variable.

Multicollinearity (VIF)

library: numpy

# VIF = diagonal of the inverse correlation matrix
print(pd.Series(np.diag(np.linalg.inv(X.corr())), index=X.columns))

VIF = 1 / (1 − R²) from regressing one predictor on the others. Above 5 deserves attention, above 10 is serious. High VIF makes individual coefficients unstable but does not hurt predictions, as long as the test set has the same correlation structure.

Row order (time structure)

print(y.autocorr())   # lag-1 autocorrelation

Near 0: rows can be treated as independent, use shuffled K-fold. Clearly nonzero: the data is ordered in time, use TimeSeriesSplit and HAC standard errors.

Y against each predictor

library: matplotlib

plt.figure(figsize=(12, 8))
for i, f in enumerate(X, 1):
    plt.subplot(2, 2, i)
    plt.scatter(df[f], y, s=5)
    plt.title(f"Y vs. {f}")
plt.tight_layout()
plt.show()

y.hist(bins=40)       # shape of the target: skew may suggest log(Y)

Look for curves (squared term), steps or thresholds (indicator), and fans (interaction or changing variance). Use s=5 or alpha=0.3 when points overlap.

02OLS & residual plots

Fit the plain linear model first. It is the benchmark every later model must beat, and its residuals show what is missing.

Baseline fit

library: statsmodels

res = sm.OLS(y, sm.add_constant(X)).fit(cov_type='HC3')   # robust standard errors
res.summary()

Reading the summary

R² / Adj. R²Share of Y's variance explained in sampleAlways rises with more terms; compare models with CV error instead

Residuals against each predictor

resid = res.resid
plt.figure(figsize=(12, 8))
for i, f in enumerate(X, 1):
    plt.subplot(2, 2, i)
    plt.scatter(df[f], resid, s=5)
    plt.axhline(0, color='r')
    plt.title(f"Residuals vs. {f}")
plt.tight_layout()
plt.show()

OLS forces residuals to have zero linear correlation with each predictor, so any visible pattern is structure the model missed. A curve means wrong functional form; a fan means unequal variance or a missing interaction. Residuals vs. fitted can look clean even when a U-shaped effect is missing, because the fitted values barely use that variable.

Fitted values and normality

plt.scatter(res.fittedvalues, resid, s=5); plt.axhline(0, color='r'); plt.show()
sm.qqplot(resid, line='s'); plt.show()
print(resid.skew(), resid.kurt())   # kurt() is excess kurtosis: 0 = normal

Patterns found here become the candidate features tested in section 04.

03Cross-validation

Every model decision is scored on data the model did not see. This replaces a single train/test split.

The scoring function

library: sklearn.model_selection

kf = KFold(n_splits=5, shuffle=True, random_state=42)

def cv_rmse(X, model=LinearRegression()):
    scores = cross_val_score(model, X, y, cv=kf, scoring='neg_root_mean_squared_error')
    return -scores.mean()

print('baseline:', cv_rmse(X))

5-fold CV trains on four fifths and scores on the last fifth, rotating so every row is scored once. It uses all the data and has less noise than one 80/20 split. Keep the same kf for every comparison so the folds match.

Overfitting check

print('train RMSE:', np.sqrt((res.resid ** 2).mean()))   # res = baseline OLS from section 02
print('CV RMSE:   ', cv_rmse(X))

Nearly equal: no overfitting. CV much worse than train: the model is fitting noise. Repeat this check on the final model in section 05.

Variants

SituationUse
Rows ordered in timeTimeSeriesSplit(n_splits=5) in place of kf
Kept duplicate rowsGroupKFold(5) with groups=df.groupby(list(X.columns)).ngroup()
Want MAE or R²scoring='neg_mean_absolute_error' or 'r2'
Error bars on the comparisonRepeatedKFold(n_splits=5, n_repeats=5), report mean ± std

Talking point. "I used 5-fold CV instead of a single holdout because it uses all the data and gives a lower-variance error estimate; then I refit on the full training set for the final predictions."

04Feature engineering

Try candidate terms one at a time, keep only those that clearly lower CV error and match what the plots showed.

Select: squared terms

for f in X:
    X_try = X.copy()
    X_try[f + '_sq'] = X[f] ** 2
    print(f, round(cv_rmse(X_try), 3))

Select: pairwise interactions (on top of the kept square)

X_sq = X.copy()
X_sq['X2_sq'] = X['X2'] ** 2

for a, b in combinations(X.columns, 2):
    X_try = X_sq.copy()
    X_try[a + '_' + b] = X[a] * X[b]
    print(a, b, round(cv_rmse(X_try), 3))

Other transforms worth one line each

X_try = X.copy()
X_try['X1_log']  = np.log(X['X1'] - X['X1'].min() + 1)  # log needs positive values
X_try['X2_abs']  = (X['X2'] - 5).abs()                   # V-shape around a point
X_try['X1_high'] = (X['X1'] > 6).astype(int)             # threshold / step
print(round(cv_rmse(X_try), 3))

Add: one function used for train and test

def add_features(data):
    data = data.copy()                 # never modify the original table
    data['X2_sq'] = data['X2'] ** 2
    data['X1_X3'] = data['X1'] * data['X3']
    return data

X_new = add_features(X)
print('with new features:', cv_rmse(X_new))

Without .copy() the function adds columns to X itself, so every later "baseline" comparison silently runs on engineered features. Restart and run all after changing it.

Deciding to drop a variable

print('with X4:   ', cv_rmse(X_new))
print('without X4:', cv_rmse(X_new.drop(columns='X4')))

If CV error is unchanged and the coefficient is insignificant, drop it for a simpler, more stable model. Add the drop to the function, so train and test stay consistent:

def add_features(data):
    data = data.copy()
    data['X2_sq'] = data['X2'] ** 2
    data['X1_X3'] = data['X1'] * data['X3']
    data = data.drop(columns='X4')     # redundant with X1
    return data

X_final = add_features(X)

Check: three-way interactions (to justify stopping)

for a, b, c in combinations(X.columns, 3):
    X_try = X_final.copy()
    X_try[a + '_' + b + '_' + c] = X[a] * X[b] * X[c]
    print(a, b, c, round(cv_rmse(X_try), 3))

If no line improves meaningfully on cv_rmse(X_final), stop at two-way terms.

Why stop at two-way interactions

  • Higher-order effects are rarely large (hierarchy principle).
  • They are hard to interpret and need all lower-order terms included.
  • The number of candidates grows fast, which invites overfitting through the search.
  • A depth-3 gradient boosting model can capture three-way effects; if it loses to your linear model, none large remain.

05Functional form selection

Compare simple to flexible models on the same folds. Each line answers one question about the final choice.

One line per model

print('Baseline OLS:      ', cv_rmse(X))
print('OLS + features:    ', cv_rmse(X_final))
print('Ridge:             ', cv_rmse(X_final, make_pipeline(StandardScaler(), RidgeCV())))
print('Lasso:             ', cv_rmse(X_final, make_pipeline(StandardScaler(), LassoCV())))
print('Huber:             ', cv_rmse(X_final, make_pipeline(StandardScaler(), HuberRegressor())))
print('Gradient boosting: ', cv_rmse(X, HistGradientBoostingRegressor(max_depth=3)))
print('Random forest:     ', cv_rmse(X, RandomForestRegressor(n_estimators=300, random_state=0)))
ModelScalingIf it matches OLSIf it beats OLS
RidgeYes, in a pipelineNo overfitting to fixCoefficients were too noisy; consider using it
LassoYes, in a pipelineEvery term carries signalSome terms were noise; check which it zeroed
HuberYes, in a pipelineOutliers aren't distorting the fitOutliers matter; mention heavy tails
Gradient boosting / forestNoFeatures capture the structureNonlinearity remains; look for it in residuals

Run tree models on the raw X: the point is that a flexible model given only the original variables still cannot beat your hand-built features.

Which terms Lasso kept

lasso = make_pipeline(StandardScaler(), LassoCV()).fit(X_final, y)
print(pd.Series(lasso[-1].coef_, index=X_final.columns))

Final model

final = sm.OLS(y, sm.add_constant(X_final)).fit(cov_type='HC3')
final.summary()

Refit on the full training set. Then check it and interpret it with the blocks below.

Residuals of the final model

resid = final.resid
plt.figure(figsize=(12, 8))
for i, f in enumerate(X, 1):
    plt.subplot(2, 2, i)
    plt.scatter(df[f], resid, s=5)
    plt.axhline(0, color='r')
    plt.title(f"Final residuals vs. {f}")
plt.tight_layout()
plt.show()

Flat plots against every original predictor mean the specification captures the structure.

Overfitting check on the final model

print('train RMSE:', np.sqrt((final.resid ** 2).mean()))
print('CV RMSE:   ', cv_rmse(X_final))

Marginal effects with squares and interactions

b = final.params
print('X2 minimum at:', -b['X2'] / (2 * b['X2_sq']))
print('Effect of X3 at mean X1:', b['X3'] + b['X1_X3'] * X['X1'].mean())
print('Effect of X3 is zero at X1 =', -b['X3'] / b['X1_X3'])

With Y = … + b₃X₃ + b₁₃X₁X₃, the effect of X₃ is b₃ + b₁₃X₁: it depends on the level of X₁. With b₂X₂ + b₂₂X₂², the turning point is at −b₂ / (2b₂₂).

06Predict & deliver

Apply the same feature function to the test set, check it, predict, and save.

Compare test and train ranges

print(pd.concat({'train': X.agg(['min', 'max']),
                 'test':  test[X.columns].agg(['min', 'max'])}))
print(test.isna().sum())
print(test[X.columns].corr() - X.corr())   # has the correlation structure changed?

Squared and interaction terms extrapolate badly. If test values fall outside the training range, say so.

Predict

X_test = add_features(test[X.columns])
test_pred = final.predict(sm.add_constant(X_test, has_constant='add'))
print(test_pred.describe())   # compare with y.describe()

The spread of predictions should be a bit below the spread of Y. Much smaller usually means the wrong model or missing features. Use has_constant='add' so the intercept is never silently skipped.

Save the CSV

pd.DataFrame({'Y': test_pred}).to_csv('predictions.csv', index=False)

# if the test file has an ID column
pd.DataFrame({'id': test['id'], 'Y': test_pred}).to_csv('predictions.csv', index=False)

check = pd.read_csv('predictions.csv')
print(check.shape, len(test))   # same number of rows, same order

{'Y': test_pred} builds a one-column table named Y. index=False stops pandas writing the row numbers as an extra column.

07Pitfalls & extras

Quick checks and reference material for the parts that tend to go wrong under time pressure.

Common bugs

BugSymptomFix
Feature function without .copy()Baseline and test comparisons show engineered columnsdata = data.copy() first line
Predicting with the baseline modelPrediction std far below Y's stdPredict with final on add_features(test)
Scaler fitted on all dataCV error looks too goodPut the scaler inside make_pipeline
Intercept missing in testShape mismatch or shifted predictionshas_constant='add'
Notebook run out of orderResults you can't reproduceRestart kernel and run all before submitting
Y scaled or loggedPredictions in the wrong unitsTransform predictions back before saving

Concepts in one line

TermMeaning
RMSETypical prediction error in Y's units; the main comparison metric
OverfittingFitting noise: train error low, CV error high
MulticollinearityCorrelated predictors: unstable coefficients, predictions fine
Omitted variable biasA missing variable correlated with an included one biases its coefficient; residual plots can't detect it
HeteroskedasticityResidual spread changes with X; use HC3 standard errors
NormalizationNot needed for OLS predictions; needed for Ridge, Lasso, KNN; never scale Y

Optional: prediction intervals

# empirical: robust to heavy-tailed residuals
lo, hi = np.percentile(final.resid, [2.5, 97.5])
intervals = pd.DataFrame({'Y': test_pred, 'lo': test_pred + lo, 'hi': test_pred + hi})

Before you submit

  • Restart kernel, run all, no errors.
  • Every placeholder markdown cell replaced with a finding.
  • Final model includes the chosen features and nothing else.
  • CSV row count equals test row count; file name as requested.
